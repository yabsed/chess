# asyncio의 실행 순서: 왜 A는 계속 실행되고 B는 기다리는가?

Python의 `asyncio`는 여러 작업을 동시에 관리할 수 있지만, 각 작업의 Python 코드가 반드시 동시에 실행되는 것은 아니다. 이를 이해하기 위해 서로 다른 실행 특성을 가진 두 작업 A와 B를 생각해 보자.

**Task A**는 한 번 실행할 때마다 3초가 걸리는 계산을 수행한다. 계산이 끝나면 `await asyncio.sleep(0)`을 호출하여 실행권을 양보하지만, 가능한 한 빨리 다음 계산을 시작하려 한다.

반면 **Task B**는 매우 짧은 작업을 수행한 뒤 `await asyncio.sleep(0.5)`를 호출한다. 즉, 실행을 마친 후 최소 0.5초 동안 기다렸다가 다시 실행되기를 원하는 작업이다.

## 1. 실제 실행 순서

두 작업이 하나의 Event Loop에서 실행될 때, 다음과 같은 실행 순서가 나타날 수 있다.

```text
0초     A 계산 시작
        │
        │ A 계산 (3초)
        ▼
3초     A 계산 종료 → sleep(0)
        B 실행! → sleep(0.5)
        A 계산 시작
        │
        │ A 계산 (3초)
        ▼
6초     A 계산 종료 → sleep(0)
        A 계산 시작
        │
        │ A 계산 (3초)
        ▼
9초     A 계산 종료 → sleep(0)
        A 계산 시작
        │
        │ A 계산 (3초)
        ▼
12초    A 계산 종료 → sleep(0)
        B 실행!
        A 계산 시작
```

이 실행 순서에서 흥미로운 점은 B가 0.5초를 기다리도록 설정되어 있음에도, 실제로는 약 9초가 지나서야 다시 실행된다는 사실이다.

## 2. B는 왜 3.5초에 실행되지 않았는가?

B는 3초에 `await asyncio.sleep(0.5)`를 호출했다. 따라서 3.5초가 되면 다시 실행 가능한 상태가 될 수 있다.

그러나 3.5초에는 A가 이미 다음 계산을 수행하고 있다. A의 계산은 동기 함수이므로 Event Loop가 중간에 강제로 중단시킬 수 없다.

결국 B는 A의 계산이 끝날 때까지 기다려야 한다.

문제는 A가 계산을 마친 뒤에도 B가 반드시 먼저 실행되는 것은 아니라는 점이다. `asyncio.sleep(0)`을 호출한 A는 실행권을 양보하지만, 동시에 자신을 다시 실행 가능한 작업으로 예약한다.

CPython의 Event Loop에서는 실행 대기 큐와 타이머 콜백의 처리 순서에 따라 A가 B보다 먼저 재개될 수 있다. 위 사례에서는 이 과정이 반복되면서 B의 실행이 12초까지 지연된 것이다.

물론 A가 정확히 세 번 연속 실행되는 것은 보장된 규칙이 아니다. 이는 해당 실행에서 관찰된 스케줄링 결과다.

## 3. asyncio의 본질

두 작업의 행동을 간단히 표현하면 다음과 같다.

- **A:** 3초 동안 계산한 뒤 실행권을 잠시 양보하지만, 곧바로 다시 계산하기를 원한다.
- **B:** 짧은 작업을 수행한 뒤 0.5초를 기다린다. 그러나 기다림이 끝나더라도 Event Loop가 바쁘면 즉시 실행되지 못한다.

여기서 중요한 점은 `asyncio.sleep(0)`과 `asyncio.sleep(0.5)` 모두 실행권을 양보한다는 것이다. 다만 전자는 가능한 한 빨리 재개되기를 요청하고, 후자는 최소 0.5초가 지난 뒤 재개될 수 있도록 타이머를 설정한다.

따라서 `asyncio`의 동시성은 여러 코루틴의 Python 코드를 동시에 계산하는 방식이 아니다. **각 코루틴이 자발적으로 실행권을 양보하면 Event Loop가 다른 작업을 실행하는 방식**이다.

이러한 구조에서는 하나의 긴 동기 작업만으로도 다른 모든 코루틴의 실행이 지연될 수 있다. 또한 `asyncio.sleep(0.5)`는 정확한 0.5초 주기를 보장하지 않는다. 그것은 최소 대기시간을 지정할 뿐이다.

결국 `asyncio`는 여러 작업의 대기시간을 효율적으로 활용하는 동시성 시스템이지, CPU 시간을 강제로 분할하거나 실행 시점을 정확하게 보장하는 실시간 스케줄러는 아니다.
